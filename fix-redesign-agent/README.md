# Fix & Redesign Agent

Persistent user rules for every redesign: [REDESIGN_RULES.md](docs/REDESIGN_RULES.md).
Use the red DS Button `brand` variant for primary actions; the black `primary` CTA
is prohibited. Preserve original layout and interactions, and derive missing local
variants from existing DS tokens. R3/R4 enforce explicit edit guards; see the rules
for the limits of automatic validation.

Takes an existing **audit-agent** run whose Fix Plan has been reviewed, applies only the findings a human marked **Fix** to the page against the Ken Design System, and delivers a **running React preview**: runnable React source plus a localhost URL, generated from the run's own captured evidence and verified before the human approval gate (G2). Every run also records before/after captures, the edit plan, per-finding accounting and a PASS / PARTIAL / FAIL verdict that is never faked.

## Startup input

`Run ID` (or `Run Name`) **+ Mode** (`full-page` | `selected-sections`) — nothing else. The Fix Plan, audit data, evidence screenshots and Design System are resolved automatically (`find-run`, `data.json`, `fix-plan.json`, the configured Design System checkout). Output location is automatic.

```bash
pnpm run agent redesign --run-id <id> --mode selected-sections      # or --run-name "<name>"
```

`--mode` is required for a real run. The mode decides what the preview contains:

| Mode | The React preview renders |
|---|---|
| **Selected Sections** | only the sections that contain a finding marked `fix`, each **complete** (original content, composition and order), with the verified DS fixes applied. Unselected sections and the global header/footer are **absent**, not hidden or marked. |
| **Full Page** | every page-specific section in page order (sections with no findings are rendered unchanged); the global header and footer stay excluded. |

## What a run produces

```
projects/<project>/redesigns/<sourceRunId>-redesign-<stamp>/
  preview-app/            ← the DEFAULT deliverable: runnable React source (Vite + React 19 + the Ken DS)
  preview/verification.json   ← the pre-G2 verification (scope, content, DS fixes, targets, interactions, runtime)
  preview/fidelity.json  correction-log.json   ← design/state comparison with the original; what the correction loop did and what is still open
  redesign/PREVIEW.md     ← URL, source path, every check, what is simulated / not reproduced
  redesign/finding-accounting.md|json   ← every Fix finding: fixed (measured) · DS component (measured) · unresolved · not in preview
  context/                ← mapping, scope, applied edits, captured behaviour of the original page, resolved-targets.json, design-baseline.json, correction-state.json
  redesign.html …         ← the static HTML export: a REFERENCE snapshot only, never the deliverable
```

The preview is **generated by the pipeline, not hand-built per run**, and the pipeline never falls back to static HTML: if the preview cannot be generated, built, served or measured, the run fails at R8 with the reason.

```bash
pnpm run agent preview <redesignRunId>                 # print the URL; start the server if needed
pnpm run agent preview <redesignRunId> --regenerate    # regenerate + rebuild + re-verify from the run's saved evidence
pnpm run agent preview <redesignRunId> --stop
pnpm run agent serve <redesignRunId> [--static]        # serve the preview (default) or the static snapshot
```

## Verification before G2 (nothing is claimed that was not measured)

R8 verifies the **running** preview in a real browser before the approval gate asks anyone for visual approval:

- **Scope** — the rendered sections equal the set derived independently from `fix-plan.json` + `data.json` (not from the mapper's own stamps), in original order, with no unselected section, no global header/footer, no leaked text.
- **Content preservation** — per section: all original text, every link and destination, every image loaded, heading structure, rendered height within 10%.
- **DS fixes, measured** — each Fix finding's audit-expected values are read from the *rendered* preview (`getComputedStyle`), design-system components are measured at the component itself. An element merely being present is never proof. Rule-driven findings (e.g. R1.4 typeface) are measured too.
- **Interactions** — before any edit, **B1** records how the *original* page behaves (hover, click, edits to inputs/sliders/selects, scroll-linked changes, CSS animations, sticky) read-only; the preview is probed the same way and compared. Behaviour that cannot be reproduced is listed as *not reproduced*, never silently passed.
- **Resolved targets** — the Resolver (node **RV**, before any edit) turns a missing or unresolved audit expectation into a verified target, a *preserved* property or a specific gap (`context/resolved-targets.json`; the audit data is never edited). R3 plans, R4 applies and R8 measures the **same** targets, each in its own state (default, real hover, keyboard focus).
- **Design & state fidelity** — the original's default, hover and focus styles, columns/grouping/order, alignment and sticky pin/release are captured once before any edit (immutable, hash-bound) and compared with the preview under the same conditions. Only a change a resolved target authorizes (finding + property + state) may differ; a card that is black by default and white on hover keeps both when only its radius is fixed.
- **Bounded correction loop** — a regression becomes actionable feedback (element, state, viewport, expected, observed) routed to the preview generator or the planner, re-rendered and rechecked inside **one** budget (`fidelity.*` in the config). It stops on pass, a concrete blocker, no progress or an exhausted budget; whatever is still open is reported at G2 (`correction-log.json`, `required.satisfied`) and is never passed.
- **Verified, failed, unverified** — every check is one of the three and they are never merged. A fidelity verdict of `incomplete` (nothing regressed, a required check could not be verified) and an `unverified` preserve decision are open required checks, reported with their reason at G2 and in `correction-log.json`, never a pass. "Preserved" is claimed only when the same element/property/state was compared on both pages and agrees.
- **Overall status** — PASS / FAIL / INCOMPLETE, identical in `verification.json`, `pv-status.json`, the preview bar, PREVIEW.md, the CLI and G2. INCOMPLETE = nothing failed but required evidence is missing (listed as gaps); optional limitations are listed separately as disclosed. G2 on FAIL needs `--accept-preview-failures`; on INCOMPLETE the decision note records the accepted unverified requirements.
- **One persisted correction budget** — 2 cycles / 3 verifications / 15 min of active time per run and plan in `context/correction-state.json`, restored by `resume` and `preview --regenerate`; reserved before the work starts; exhausted → no new verification, previous valid evidence kept, INCOMPLETE. Only `--reset-budget` restarts it.
- **Preview failures reopen findings** — if the rendered preview fails a target the live page measured fixed, R3 is re-asked with structured feedback for exactly those properties/states (earlier edits kept, same shared budget) and the result is re-verified.
- **Reference colours become DS colours** — an approved reference's colour is read with alpha/state/theme and mapped to the exact DS token or the nearest suitable one (polarity, strength, ΔE ≤ 2 on the measured backdrop, visible border, contrast); nothing suitable → the pattern is refused for that colour. Planner, applier and verifier use the same derived value; provenance is in `resolved-targets.json`. Reference components are matched by purpose (category), not by tag or role. Details: `docs/ARCHITECTURE.md` §8d.6.
- **Runtime** — no request leaves the preview, no console error, no horizontal overflow at 1440/390px, every asset embedded or downloaded.

G2 shows the URL, the verification verdict and the findings measured fixed. `decide G2 --outcome approve` is refused when verification failed unless `--accept-preview-failures` is given (the failed checks are written into the decision note). G2 is always a human decision.

### When the generator cannot reproduce something

JavaScript-driven widgets (scroll-linked paths, calculators, accordions whose answers are only rendered on click) are not derivable from a static snapshot. They are reported as not reproduced. To close such a gap for a page, add a hand-authored React module to `<run>/preview-overrides/`, register it in `<run>/context/design-decisions.json` (`overrides`), and `preview <id> --regenerate`. The same file records per-finding design decisions (`reuse-existing`, `compose-existing`, `propose-variant`, `preserve-existing`; see the Design Review Resolver in the skill). Overrides are labelled hand-authored in the verification; their behaviour is covered by an optional `preview-overrides/checks.mjs`.

## Status

Implemented and tested: R1 resolve · R2 capture · C2 element mapping · scope/G1 · **B1 behaviour + design-baseline capture** · **RV resolver** · R3 plan · R4 apply · R5 compare · R6 manifest · R7 static export · **R8 React preview (generate · build · serve · verify · correct)** · G2 gate whose fingerprint covers the preview, the resolved targets, the baseline, the fidelity report and the correction outcome · judgment provider (`claude-session`). Component creation and publishing (L-series, G3–G5) are out of scope and refused by the CLI. Source mode (editing the website's own repository) is a proposal in `docs/ARCHITECTURE.md` and blocked on the site's source being available.

Known limits are listed in `docs/ARCHITECTURE.md` §8c.7 and §8d.5. **Approved reference projects** (a read-only allowlist consulted only for a real DS gap) are in `references/approved-projects.json`.

## Commands

```bash
pnpm install
pnpm build                                   # tsc --noEmit
pnpm test                                    # unit + integration (real Chromium, real Design System)

pnpm run agent redesign --run-id <id> --dry-run                   # R1 only: resolve, validate, load DS, print the Fix findings (writes nothing)
pnpm run agent redesign --run-id <id> --mode full-page|selected-sections
pnpm run agent resolve-run --run-id <id>                          # just the linkage check
pnpm run agent list                                               # redesign runs in projects/
pnpm run agent trace <redesignRunId>                              # node/iteration spans of a run
pnpm run agent resume <redesignRunId>                             # resume a checkpointed run (a judgment pause or a decided gate)
pnpm run agent judgment status|show|submit …                      # claude-session judgment bundles (below)
pnpm run agent decide <redesignRunId> --gate G2 --outcome approve [--note …] [--accept-preview-failures]
```

**Judgment provider (`judgmentProvider` in config, default `"claude-session"`):** C2/RV/R3/R5's judgment is performed by the running Claude Code session itself — no `ANTHROPIC_API_KEY`, no external model call. When one of those nodes is reached, the run writes a pending bundle under `<runDir>/judgments/` and checkpoints as `awaiting-judgment`; the Session Agent reads it (`judgment show`), performs the judgment (opening the referenced screenshots for R5), and records it (`judgment submit`), which validates against the node's real schema and resumes the pipeline. Set `judgmentProvider: "anthropic-api"` to call the API directly instead.

**Production safety:** R2/B1 are read-only navigation (politeness-paced; every non-GET request and analytics call aborted during B1; links and submit controls are never clicked, forms never submitted). The generated preview contacts nothing but itself.
